Hai Sai Lầm Trong Tư Duy Khi Dùng Rich Text (.docx) Cho Dự Án Mã NguồnSai lầm 1: Nhầm lẫn giữa tệp nhị phân mã hóa (Binary/Rich Text) và văn bản mã nguồn thuần túy (Plain Text).
File .docx thực chất là một lưu lưu trữ ZIP chứa nhiều file mã hóa XML, cấu hình định dạng, và siêu dữ liệu (metadata). Git được thiết kế để theo dõi thay đổi theo từng dòng chữ (line-by-line). Do file .docx là dạng nhị phân mã hóa, Git không thể đọc hay so sánh nội dung bên trong. Khi sửa dù chỉ một dấu phẩy, toàn bộ cấu trúc mã hóa bị thay đổi khiến Git hiểu lầm toàn bộ file đã bị xóa và thay mới, gây ra Conflict (Xung đột) trên toàn bộ file khi hợp nhất nhánh.Sai lầm 2: Phụ thuộc vào phần mềm độc quyền để xem/đánh giá nội dung.
Tệp Rich Text yêu cầu phần mềm chuyên dụng (Microsoft Word, Google Docs) để mở và render giao diện. Trình duyệt web cũng như giao diện GitHub không thể tự động render nhanh nội dung .docx, làm gián đoạn quy trình làm việc nhóm vì thành viên buộc phải tải file về máy local mới xem được.2.
